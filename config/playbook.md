## 0. 前提 — 何を最適化しているのか

cross-com.jp(合同会社クロスコム)は **Agentforce導入・定着支援** と
**Agentic CRM/CRMデータ設計支援** を提供する。差別化の軸(KBF)は:

- **ベンダー中立** — 特定製品の販売代理ではなく、設計から入る立場
- **設計支援** — ツール選定の前にCRM/データ設計から関与する方法論
- **定着支援** — 導入して終わりではなく現場に定着させるところまで伴走
- **Agentforce専門性** — Salesforce Agentforce に絞った深さ
- **ソリューション営業知見** — 営業実務の理解に裏打ちされた設計

観測は2つのPillarに分かれる:

| Pillar | 狙い | プロンプト |
|--------|------|-----------|
| A | Agentforce文脈での想起 | A-1 導入支援会社探し / A-2 定着支援 / A-3 費用相場 |
| B | Agentic CRM・ベンダー中立文脈での想起 | B-1 カテゴリ認知 / B-2 中立ポジション / B-3 設計ファースト |
| entity | エンティティ情報の鮮度 | E-1 会社そのものの説明 |

**最終ゴールは「AIに推薦される状態」であって、記事本数やPV数ではない。**
したがってアクションは常に「LLMが引用しうる一次情報を、引用されうる形で置く」に帰着する。

## P-2 言及消失(mention_gained だったものが FALSE に戻る)

**状態**
過去に言及実績のある prompt_id × model で、直近3観測日連続で言及が消えた。

**原因仮説(可能性の高い順)**

1. **競合の情報供給が増えて相対的に押し出された** — 同じ質問に対する候補が増え、
   上位N社に入らなくなった。R-P15 や SoV の競合増加と同時発火していれば確度が高い。
2. **引用元ページの鮮度低下** — 最終更新が古くなり、モデルが新しい情報源を優先した。
3. **モデル側の更新** — インデックス更新やWeb検索結果の変動。自社要因ではない場合もある。
   1〜2週で自然回復することがあるため、単発では動かない。

**改善アクション**

- 該当 prompt_id の CEP(想定検索文脈)に対応する**事例・実績ページを1本更新**する。
  更新は日付を変えるだけでなく、**具体的な数値・企業規模・課題**を追加する。
- 競合が新たに出現しているなら、その競合が引用されているページを確認し、
  **こちらに欠けている情報の型**(価格の明示、導入期間、支援範囲の粒度)を特定する。
- 両モデルで同時に消えた場合のみ優先度「高」。片方だけなら1週様子見。

## P-4 言及率の急改善(横展開の好機)

**状態**
pillar別 mention_rate の7日平均が前週比 +0.10 以上。

**原因仮説**

1. 直前に公開・更新したコンテンツが効いた(最も多い)。
2. 競合の露出が一時的に落ちた(自社要因ではない)。
3. モデル側の更新でたまたま拾われた。

**改善アクション**

- **何が効いたかを1つに特定する。** 直近2週の公開・更新履歴と照合し、
  効いた可能性が最も高いページを1本挙げる。
- 効いたページの**構造を他Pillarに複製する**。見出しの立て方、Q&A形式、
  数値の入れ方といった「形」を移植する。内容の使い回しではない。
- 改善が競合の一時的後退による場合は横展開しない(再現性がない)。
  SoVで競合の出現数が同時に落ちていないか必ず確認する。

## P-5 万年下位(推薦リストには入るが順位が低い)

**状態**
同一 prompt_id の rank 中央値が 6 位以下(=順位として悪い)の週が4週連続。

**原因仮説**

1. **一次情報の厚みが競合に劣る** — 言及はされるが「筆頭で挙げる理由」が弱い。
2. **specificity の不足** — 「何でもできます」に見えており、
   質問の具体文脈(定着しない/中立性が欲しい/費用感を知りたい)に刺さっていない。
3. 第三者言及(導入事例、メディア掲載、登壇)が少なく、裏取りの材料が乏しい。

**改善アクション**

- 該当 prompt_id の CEP に**1対1で対応するページを新規に1本**作る。
  既存ページへの追記ではなく、質問文をそのまま見出しにできる粒度で独立させる。
- **数値を入れる。** 支援社数、平均導入期間、定着率、費用レンジ。
  LLMは検証可能な数値を持つ情報源を優先して引用する傾向がある。
- 上位に入っている競合を1社選び、そのページの**情報の粒度**を比較する。
  勝てない要素(規模・知名度)ではなく、勝てる要素(専門性の深さ)で差を作る。

## P-7 ネガティブ/古い情報の検知(最優先)

**状態**
直近7日に `negative_or_outdated = TRUE` の観測が1件以上。

**原因仮説**

1. **旧事業(MA/メール配信・BtoBマーケ支援)の情報が残存している** — 最も多い。
   旧サイト・旧記事・外部メディアの古いプロフィールが引用され続けている。
2. 誤情報(提供していないサービス、誤った会社規模・所在地・沿革)。
3. 第三者サイトの古い記述(まとめ記事、ディレクトリサイト)。

**改善アクション(このパターンだけは即日着手)**

- `negative_detail` の記述内容を確認し、**引用元URLを特定する**。
  自社ドメインなら該当ページを修正または 301 で現行ページへ統合する。
- 外部サイトが原因なら、**修正依頼を出す**。依頼できない場合は、
  自社側に「現在の事業内容」を明示した正規ページを用意し、そちらが引用されるよう
  構造化データ(Organization / sameAs)と内部リンクを整える。
- E-1 の回答は会社そのものの説明であり、**採用・商談に直接影響する**。
  ネガティブ検知は他のどのパターンより優先する。

## P-8 旧事業URLの引用(エンティティ情報の汚染)

**状態**
E-1 の `cited_crosscom_urls` に旧事業パス(`config/legacy_paths.yaml`)が含まれる。

**原因仮説**

1. 旧記事が依然として自社ドメイン内で最も「会社を説明している」ページになっている。
2. 現行の事業説明ページの情報量が薄く、旧記事に負けている。
3. 旧記事に外部リンクが集まっており、権威が高いままになっている。

**改善アクション**

- 旧事業ページを **301リダイレクト**で現行の事業説明ページへ統合する。
  削除(404)ではなくリダイレクトにする(被リンクの権威を引き継ぐため)。
- 統合できない事情がある場合は、旧記事の冒頭に**現在の事業を明示した導線**を置く。
- 会社概要ページに **Organization 構造化データ**(事業内容・設立・代表・sameAs)を実装し、
  「クロスコムとは何の会社か」の一次情報を1箇所に確定させる。

## P-15 競合の定着(自社不在のプロンプト)

**状態**
自社の言及がない prompt_id において、同一競合が直近7日に両モデルで出現し、
かつ4週連続で出現している。

**原因仮説**

1. その競合が当該CEPに**専用の一次情報**を持っている(自社にはない)。
2. その競合が第三者メディア・比較記事で繰り返し言及されている。
3. カテゴリ自体で自社がまだ想起圏に入っていない(Pillar Bで起きやすい)。

**改善アクション**

- 該当競合の**引用されているページを実際に読む**。何を書いていて自社に無いのかを
  1行で言語化する(例:「費用レンジを明示している」「導入までの週次スケジュールがある」)。
- そのCEPに対する自社の**ポジションを1つ決める**。競合と同じ土俵で勝つのではなく、
  ベンダー中立・設計ファーストといった KBF のどれで差別化するかを決める。
- **競合と同じ形式のページを1本作る。** 比較表、費用、進め方、といった
  「引用しやすい構造」を優先する。文章量ではなく構造で勝つ。

## P-DROP 競合構造の変化(半減 / 新規上位入り)

**状態**
SoV上位5の競合が前週比で出現半減、または新規エンティティが上位5に入った。

**原因仮説**

1. **新規参入**:新しいプレイヤーがそのカテゴリで情報供給を始めた。
2. **競合の後退**:サイト改修・情報削除・モデル側の評価変動。
3. 観測揺れ(特に観測日数が少ない週)。

**改善アクション**

- **新規上位入り**:その企業が何者か、どのページが引用されているかを確認する。
  自社と提供領域が重なるなら、次週以降のウォッチ対象に固定する。
- **半減**:自社のシェアが相対的に上がっているタイミング。
  P-4 と同時発火していれば、そこが横展開の好機。
- 観測日数が5日未満の週の増減は**判断材料にしない**(ノイズの可能性が高い)。

## 週次レビューの進め方

1. **P-7 / P-8 が出ていたら他を見る前に着手する**(情報の正しさが最優先)。
2. 残りは**発火したパターンのうち上位3件まで**に絞る。同時に多くを動かさない。
3. 各アクションは「誰が」「何を」「いつまでに」が決められる粒度まで落とす。
   落とせないものはアクションではなく調査項目として扱う。
4. 効果判定は**最低2週**待つ。単週の変動で方針を変えない。

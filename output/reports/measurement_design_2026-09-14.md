## 2. 記事単位のGSCデータ(gsc_pages)

### 2-1. タブ定義

| 列 | 内容 |
|---|---|
| `date` | 日付(YYYY-MM-DD) |
| `page` | 記事URL。`#見出し` は落として同じ記事にまとめる |
| `impressions` | 表示回数 |
| `clicks` | クリック数 |
| `position` | 平均掲載順位(表示回数で重み付け、小数2桁) |
| `queries` | その日にその記事が表示された**匿名化されていない**クエリの種類数 |

- 鍵は `date × page`。再実行しても重複しない(upsert)。
- `gsc_branded`(指名検索)の集計は**変更していない**。別の API 呼び出しで独立に取る。

### 2-2. 取り方

| | 取得 |
|---|---|
| impressions / clicks / position | `dimensions=['page','date']` |
| queries | `dimensions=['page','query','date']` のクエリ種類数 |

- **合計は page×date から取る。** page×query×date は匿名化クエリが落ちるので、
  そこから足すと表示回数が過少になる。
- 25,000 行の上限ちょうどで返ってきた場合は `startRow` で続きを取る
  (打ち切られた応答をそのまま使うと、記事の一部が 0 クリックと区別できない形で欠ける)。
- `#見出し` 違いを1記事にまとめたとき、同じ検索結果に両方が出た表示は2回に数えられる
  (GSC のページ別集計の仕様)。記事単位の比較では、記事が2行に割れるより害が小さい。

### 2-3. 日次

`run_daily.py` が指名検索と同じ **3日前**(GSC の確定待ち)の1日分を取って書く。
タブを読むのは鍵の2列だけ(行数が増えても日次の読み取り量が膨らまない)。

## 3. 統計手法(方針)

### 3-0. 判断の原則

- **p値で合否を決めない。** 件数が小さく、有意にならないことが「効果が無い」を意味しない。
  逆に、観測日数を増やせば実務上意味のない差でも有意になる。
- 報告するのは **効果の大きさ(点推定)と不確実性の幅(95%区間)** の2つ。
- 判断は、**事前に決めた「継続判断の閾値」** と点推定・区間を突き合わせて行う。

| 判断 | 条件(形) |
|---|---|
| **継続・横展開** | 点推定が閾値以上、かつ区間の下限が「悪化」側に大きく出ていない |
| **観測を延長** | 点推定は閾値付近だが区間が広い(データが足りない) |
| **停止・見直し** | 点推定が閾値を明確に下回り、区間の上限も閾値に届かない |

> **閾値の数値は要決定。** 下の初期案は「この程度動かなければ工数に見合わない」
> という事業側の基準で決めるもので、統計から出てくる数字ではない。
> 分析を回す**前に**決めて、この表に書き込む(結果を見てから決めると後付けになる)。

| 対象 | 効果の大きさの表し方 | 継続判断の閾値(初期案・要決定) |
|---|---|---|
| 記事単位 | クリック・表示回数の**率比**(施策記事 ÷ 対照記事の変化の比) | 率比 1.20 以上(+20%) |
| サイト全体 | AI経由セッションの**水準変化・傾き変化**(週あたり) | 施策後の週平均 +3セッション |
| LLM言及率 | 言及の**オッズ比**と、率に直した差(ポイント) | +10ポイント |

### 3-1. 記事単位:差の差分析(負の二項回帰)

| 項目 | 方針 |
|---|---|
| データ | `gsc_pages` を**記事×週**に集計(日次は0が多すぎる) |
| 処置群 | `action_log` の対象URL(§4)で、実施日が入っている記事 |
| 対照群 | 施策を打っていない記事。**割合は事業判断(§5)** |
| 目的変数 | clicks(主)、impressions(副) |
| モデル | 負の二項回帰:`log E[y] = 記事固定効果 + 週固定効果 + β・(処置記事 × 実施後)` |
| 標準誤差 | 記事でクラスタ |
| 効果 | `exp(β)` = 率比。1.20 なら +20% |
| 前提の確認 | 16か月の過去データで**実施前の傾向が処置群と対照群で平行か**を見る(イベントスタディ形式で実施前の係数を並べる) |

- **負の二項を使う理由:** 記事×週のクリックは0が多く、平均より分散がずっと大きい。
  ポアソンだと区間が狭く出すぎる。
- **施策の実施日がずれる(段階的に打つ)場合**、単純な2期間の差の差は
  先に打った記事を対照に使ってしまい偏る。実施日ごとに「その時点で未実施の記事」
  だけを対照にする積み上げ型(stacked DiD)で推定する。
- **季節性:** 週固定効果で吸収する。16か月あれば前年同時期との比較も補助的に見られる。

### 3-2. サイト全体:中断時系列分析

| 項目 | 方針 |
|---|---|
| データ | 週次の系列:AI経由セッション、AI経由キーイベント(**9/1以降のみ**)、指名検索クリック |
| モデル | 区分回帰:`y = 切片 + 傾き・t + 水準変化・実施後 + 傾き変化・(t − 実施時点)・実施後` |
| 自己相関 | Newey-West 標準誤差(または ARIMA 誤差)。週次の値は前週と相関する |
| 効果 | 水準変化と傾き変化を、それぞれ区間つきで出す |

- **施策が同じ時期に集中している**(8/24 に A-003/004/005 を同日実施)。
  サイト全体の系列では1本ずつに分けられないので、**「施策期間」を1つの中断**として扱う。
  1本ずつの効果は記事単位(§3-1)で見る。
- キーイベントは 9/1 より前が欠測なので、**実施前の期間が取れず中断時系列にできない**。
  当面は水準の推移を見るだけにする。
- 正式指標(Salesforce)は 8/24 より前が存在しないので、同様に中断時系列にはできない。

### 3-3. LLM言及率:混合モデル(面をクラスタ)

| 項目 | 方針 |
|---|---|
| データ | `llm_observations` の1観測(日×プロンプト×モデル)= 1行、`mention` が 1/0 |
| モデル | 混合ロジスティック回帰:`logit P(言及) = 実施後 + モデル(gemini/claude) + (1 | 面)` |
| 面 | prompt_id(A-1〜B-3)。同じ面の観測は互いに似るので、面ごとのランダム切片で扱う |
| 効果 | 「実施後」のオッズ比と、それを率に直した差(ポイント) |

- **面をクラスタにする理由:** 6面×2モデル×毎日の観測を独立として数えると、
  実際の情報量(面は6つしかない)より区間が狭く出る。
- **判定基準の変更日**(2026-08-24 の `negative_or_outdated` 精緻化など、README の変更履歴)
  をまたぐ指標は、変更の有無を説明変数に入れるか、変更後だけで推定する。
- E-1(エンティティ質問)は分母から外す(現行の言及率と同じ定義)。

## 5. 論点:3か月の成果目標と厳密な検証(要判断)

### 5-1. トレードオフ

**3か月で成果を出すことと、効果を厳密に検証することは両立しにくい。**

| | 成果を優先 | 検証を優先 |
|---|---|---|
| 施策の打ち方 | 効きそうな記事すべてに、できるだけ早く打つ | 一部の記事をあえて打たずに残す(対照群) |
| 同時実施 | 同じ日に複数本打ってよい | 1本ずつ間隔を空ける |
| 分かること | 「全体として良くなったか」 | 「どの施策が、どれだけ効いたか」 |
| 失うもの | どれが効いたか分からない。次の打ち手を選べない | 対照に回した記事の改善が遅れる(機会損失) |

加えて、**3か月では件数が足りない指標がある。**

- 正式指標(認知経路「AI」)は月数件の見込みで、3か月では増減を区別できない。
- AI経由セッションは週0〜4件(8/11〜9/10 の実績)で、週次の判断の目安(週10件)に届いていない。
- 3か月で判断に使えるのは、件数の多い **言及率** と **記事単位の表示回数・クリック** が中心になる。

### 5-2. 対照群に回す割合は事業判断

対照群を大きくするほど推定は安定するが、改善しない記事が増える。
**これは統計が決めることではなく、機会損失をどこまで許容するかの判断。**

| 案 | 内容 | 検証 | 成果への影響 |
|---|---|---|---|
| A. 対照なし | 全記事に打つ | 実施前後の比較のみ。季節性・外部要因と分けられない | 最大 |
| B. 一部を残す | 候補記事の 20〜30% を3か月間打たない | 差の差分析ができる | 残した記事の分だけ遅れる |
| C. 時期をずらす | 全記事に打つが、半分は1.5か月遅らせる | 前半1.5か月は差の差分析ができる。最終的には全記事が改善 | 後半組が1.5か月遅れる |

> **判断に必要なもの:** 候補記事の数、施策1本あたりの工数、
> 3か月後に「どの施策が効いたか」を説明する必要があるか(次期の予算・横展開の根拠にするか)。
> 案C は両方を部分的に取れるが、どちらも完全ではない。
